Turning NullHawk into a product people pay for

A hosted (SaaS) autonomous pentest tool, self-serve, aimed at individual security researchers and bug-bounty hunters. Here's the honest path from fork to paid product.

MODEL: SaaS (you host) · BUYER: individual researchers · BASE: PentAGI fork (MIT) · v0.1 — a living plan

Read this first: the hosted-offensive problem

When you host an autonomous attack tool, every scan and exploit runs from your infrastructure. AWS, GCP and Azure all forbid outbound attack traffic to targets you can't prove consent for — they will suspend your account, and you become the legal operator of the attack.

Every serious hosted scanner (Pentest-Tools, Detectify, Intruder) solves this the same way: target-ownership verification is feature #1 — before any flow runs, the user proves the target is theirs (DNS TXT record, file on the host, or verified IP range). Build this before billing, not after.

Two design choices that fit individual researchers and cut your risk: BYO LLM key (users bring their own Anthropic/OpenAI key — your cost and liability drop) and verified-targets-only flows.

What you have vs. what you build

The PentAGI base already carries a surprising amount of the SaaS plumbing. Green is done, amber is new work, red is the non-negotiable.

Already there

Multi-tenancy

TENANT_ID isolates data, ports and sandboxes per instance — one tenant per customer is the natural unit.

Already there

Auth & accounts

Session cookies, OAuth (Google/GitHub), bearer API tokens and a password policy ship in the box.

Already there

Per-flow sandboxing

Each flow runs tools in an isolated Docker container — the compute primitive a SaaS needs.

Build

Billing & provisioning

Stripe self-serve checkout → webhook → provision a tenant. Metered caps on concurrent flows.

Critical

Target verification

DNS-TXT / file / IP-range proof of ownership, gated before a flow can target anything. Full audit log.

Critical

Abuse controls + egress

Rate limits, denylist (gov/mil/critical infra), kill switch, dedicated egress IPs on a provider that permits security testing.

Build

Remove the phone-home

Strip the VXControl cloud calls (update.pentagi.com, LICENSE_KEY) — don't depend on a competitor's infra.

Build

BYO LLM key

Let users paste their own provider key. Lower your bill, lower your liability, faster onboarding.

The phased plan

Phase 0NOW · done/next

Foundation

  • Done: fork, full NullHawk rebrand, brand assets, landing page.
  • Next: remove the VXControl phone-home; pick a hosting provider that allows pentest egress (not vanilla AWS).
  • Trademark-check "NullHawk" (EUIPO/Benelux).
Phase 1MVP · private beta

Sellable core

  • Target verification (DNS-TXT first — simplest) gating every flow.
  • Stripe self-serve signup → tenant provisioning → Solo/Pro plans.
  • BYO LLM key in onboarding; abuse caps + kill switch.
  • Your own EULA / ToS / acceptable-use (lawyer review).
Phase 2polish · public launch

What researchers love

  • Report export — clean findings PDF/Markdown is a top reason this buyer pays.
  • Usage dashboard, billing portal, email support.
  • Launch: Product Hunt, bug-bounty communities, security Twitter/Discord.
Phase 3scale

Harden & grow

  • Dedicated egress pools, abuse-ops, SOC2-lite if you move upmarket.
  • Team seats / referrals; consider a Pentest-firm tier later.

Legal checklist — get a lawyer; this is a map, not advice

▸ Own EULA + ToS ▸ Acceptable-use: authorized testing only ▸ Verified-target requirement in contract ▸ Liability cap + indemnity ▸ GDPR / DPA (EU users) ▸ Export-control review (offensive tooling) ▸ Keep upstream MIT notice (PentAGI) ▸ Abuse-report + takedown process
